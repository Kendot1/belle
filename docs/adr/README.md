# Architecture Decision Records

ADRs record durable architecture, data, security, and product-scope choices. Status is `proposed`, `accepted`, `superseded`, or `rejected`. Accepted decisions remain active until a later ADR supersedes them.

| ADR | Decision | Status |
| --- | --- | --- |
| [0001](0001-expo-sqlite-and-local-storage.md) | Expo SQLite, Drizzle, FTS5, SQLCipher, and local storage | Accepted |
| [0002](0002-rich-text-and-anchors.md) | 10tap/Tiptap document and context-based comment anchors | Accepted |
| [0003](0003-local-foundation-models.md) | Apple Foundation Models as the only AI provider | Accepted |
| [0004](0004-pdf-and-export-scope.md) | Defer PDF, attachments, and export/restore from the MVP | Accepted |
| [0005](0005-app-architecture.md) | MVP scope and application boundaries | Accepted |

The existing numbered ADRs are retained to preserve their project history; the app-architecture decision uses the next free number rather than creating duplicate ADR IDs.
